# 缺陷管理模板

> 说明：当前项目是自研练习系统，没有真实线上缺陷。下面是软件测试工作中通用的缺陷记录方式，面试时可以用来回答“你怎么提 Bug、怎么跟踪”。

## 1. 缺陷等级

| 等级 | 定义 | 例子 |
|---|---|---|
| S1 致命 | 系统不可用、数据丢失、安全漏洞 | 下单后订单丢失；任意用户可查看他人订单 |
| S2 严重 | 核心功能不可用，无绕过方案 | 无法登录；优惠券金额算错 |
| S3 一般 | 非核心功能异常，有绕过方案 | 搜索大小写不匹配；提示文案错误 |
| S4 轻微 | 样式、文案、体验问题 | 按钮错位；金额少显示一位小数 |

## 2. 优先级

| 优先级 | 含义 |
|---|---|
| P0 | 本版本必须修复，否则不能上线 |
| P1 | 本版本应修复，影响主要用户 |
| P2 | 可排到下个版本 |
| P3 | 有空再改 |

等级看“影响”，优先级看“什么时候修”。S2 不一定是 P0，比如低频后台功能。

## 3. 缺陷生命周期

```text
新建 New
  → 指派 Assigned
  → 修复 Fixed
  → 待验证 Resolved
  → 关闭 Closed / 重新打开 Reopened
```

测试同学负责：新建、复现、验证、关闭。  
开发负责：修复。  
产品/项目经理负责：优先级和排期。

## 4. 缺陷报告模板

```markdown
### 标题
[模块][等级] 一句话描述现象

### 环境
- 版本/分支：
- 操作系统：
- 浏览器：
- 测试账号：

### 前置条件
例如：已登录，购物车有 1 件商品

### 复现步骤
1. 打开……
2. 点击……
3. 输入……

### 实际结果
……

### 预期结果
……

### 复现概率
必现 / 5 次 3 次 / 偶现

### 附件
截图、录屏、请求响应、日志、订单号

### 备注
是否影响其他功能、是否有绕过方案
```

## 5. 示例（模板，不是本项目真实缺陷）

### 标题
[订单][S2] 使用 QA10 优惠券后实付金额仍按原价计算

### 环境
- 版本：ShopLite v1.0
- 浏览器：Edge 155
- 账号：qa_demo_01

### 前置条件
购物车商品小计 ¥100.00

### 复现步骤
1. 进入结算页；
2. 输入优惠券 `QA10`；
3. 点击提交订单；
4. 查看订单详情实付金额。

### 实际结果
订单显示优惠 ¥10.00，但实付仍为 ¥100.00。

### 预期结果
实付应为 ¥90.00（100 − 10）。

### 复现概率
必现

### 附件
订单号、截图、接口响应

### 备注
影响所有使用 QA10 的订单，建议 P0。

> 这个示例只用于展示格式。当前项目的优惠券用例是通的，不要把它说成真实缺陷。

## 6. 面试怎么讲缺陷管理

可以这样回答：

> 我会先确认环境和复现步骤，保证不是偶发或数据问题；然后按“标题、环境、前置条件、步骤、实际、预期、附件”提 Bug，按影响定等级、按排期定优先级。修复后我会用原步骤回归，并补一条自动化用例，防止同样的问题再出现。
